## The problem

HR teams sit on useful data in SQL Server: attendance, leave, payroll. Getting an answer out of it usually means waiting for someone who can write SQL, or exporting to Excel and rebuilding the same pivot every month.

An AI assistant can write that SQL in seconds. The reason most teams still say no is simple: nobody wants a chatbot with a connection to the payroll database.

## What I built

A small server that sits between Claude and SQL Server and speaks the Model Context Protocol. It gives Claude three tools and nothing more:

- `list_tables`: what can I read?
- `describe_table`: what columns and relations does this table have?
- `run_query`: run one SELECT and return the rows.

With these, Claude explores the schema on its own, writes the query, and answers questions such as "which department had the most late arrivals in October?" or "who has a pending leave request, and who approves it?"

## How it stays safe

The design question was not "can Claude query the database" but "what happens when it writes the wrong thing". Four guards answer that:

1. **Two walls against writes.** The server connects with a database login that only has SELECT permission, so SQL Server refuses writes by itself. In front of that, every query is checked: one statement, SELECT only, no write or admin keywords. Either wall is enough alone.
2. **Row limit.** Results are capped (100 rows by default). When rows are cut, Claude is told so, and it aggregates instead of presenting a partial list as complete.
3. **Timeout.** A query that runs too long is cancelled, so one careless join cannot slow the database for everyone else.
4. **Audit log.** Every call is written down: time, the exact SQL, allowed or blocked, rows returned, duration. IT can review what the assistant did, line by line.

## Demo data

The repository includes a fictional HR database: 6 departments, 60 employees, two months of attendance, leave requests and three payroll periods. Everything is generated by one SQL script. No real company or employee data is involved, and one Docker command sets it up.

## Result

- Runs locally in about five minutes once the SQL Server image is downloaded: Docker, one seed script, one entry in the Claude Desktop config.
- Write attempts are refused and logged; covered by automated tests for the query check, row limit, timeout and audit log.
- About 200 lines of TypeScript, three dependencies. Small enough for a client's IT team to read in full before approving it.

## Stack

TypeScript, Node.js, Model Context Protocol SDK, SQL Server 2022, Docker.

## What this looks like for a client

The same connector points at a real HRIS or payroll database: a dedicated read-only login, views that hide sensitive columns, and the audit log shipped to wherever IT keeps its logs. Typical first uses are monthly attendance summaries, leave balance questions and headcount reports that today are built by hand.
